- Create: `components/games/pacman-logic/maze.ts`
- Test: `components/games/pacman-logic/maze.test.ts`

**Interfaces:**
- Produces: `parseMaze(rows: string[]): ParsedMaze` where `ParsedMaze = { cols: number; rows: number; walls: Uint8Array; pellets: Set<number>; powerPellets: Set<number>; tunnels: number[]; ghostHouse: { door: number; cells: number[] }; pacmanSpawn: number; fruitCell: number; adjacency: Uint8Array }` (cell index = `y * cols + x`; adjacency bitmask bit0=up bit1=left bit2=down bit3=right).

Rules (from spec legend section): grid is 28×31; exactly 4 power pellets; 230–250 pellets; every pellet/power reachable from `pacmanSpawn` by flood-fill over non-wall cells; tunnel cells come in left/right pairs on the same row; ghost house has exactly one door cell.

- [ ] **Step 2:** Write `maze.test.ts` with failing tests using a small 8×9 fixture maze written inline in the test (legend from spec: `#` wall, `.` pellet, `o` power, `T` tunnel, `-` house door, `H` house cell, `P` pacman spawn, `F` fruit cell, ` ` empty): asserts for `parseMaze` (cols/rows, pellet count, adjacency of a corner cell, tunnel pairing) and for `validateMaze` (valid fixture → `[]`; fixture with a walled-off pellet → violation mentioning that cell; fixture with 3 power pellets → violation). NOTE: the 8×9 fixture relaxes the 28×31 rule — pass grid dims as optional params `validateMaze(m, { expectDims: [8, 9], pelletRange: [10, 999] })` so production defaults stay strict.

### Task 3: Ghost AI module (targeting + mode machine)

**Files:**
- Create: `components/games/pacman-logic/ghosts.ts`
- Test: `components/games/pacman-logic/ghosts.test.ts`

**Interfaces:**
- Consumes: `ParsedMaze` from Task 1.
- Produces:
  - `type GhostId = 'blinky' | 'pinky' | 'inky' | 'clyde'`
  - `type Mode = 'scatter' | 'chase' | 'frightened' | 'eyes'`
  - `chaseTarget(id: GhostId, s: TargetState): number` with `TargetState = { pacmanCell: number; pacmanDir: 0|1|2|3; blinkyCell: number; ghostCell: number; cols: number }` — implements the 4 classic targets from the spec (Pinky 4 cells ahead, Inky reflected Blinky vector, Clyde 8-cell threshold to scatter corner).
  - `scatterTarget(id: GhostId, m: ParsedMaze): number` — 4 corners.
  - `nextDir(ghostCell: number, currentDir: 0|1|2|3, targetCell: number, m: ParsedMaze, frightened: boolean, rng: () => number): 0|1|2|3` — no 180° reversal unless dead-end; tie-break up>left>down>right; frightened picks pseudo-random legal dir via injected `rng`.
  - `modeSchedule(level: number): { phase: Mode; durationMs: number }[]` — from spec DIFFICULTY table: scatter(scatterS)→chase(20 s) ×4 cycles, then permanent chase.

- [ ] **Step 1:** Write failing tests with exact cell arithmetic on a 28-col grid: Blinky targets pacman cell; Pinky +4 in facing dir; Inky = `blinky + 2*(pacmanAhead2 − blinky)`; Clyde far→pacman / near→corner (both sides of the 8-cell threshold); `nextDir` never reverses at a T-junction, DOES reverse in a dead-end, respects tie-break order with equidistant options; `modeSchedule(1)` starts scatter 7000 ms (spec row 1) and ends in permanent chase.
